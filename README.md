# 🎨 자비샵

등급별 랜덤 그림 판매 플랫폼. **웹사이트(Next.js)**와 **디스코드 봇**이 완전히 같은 데이터베이스와 핵심 로직을 공유해서, 어느 쪽에서 구매하든 결과가 100% 동일합니다.

- 결제는 실제 PG 연동 없이 **계좌이체 + 관리자 수동 확인 + 포인트제**로 동작합니다.
- 랜덤 구매는 "포인트 차감 + 재고 원자적 선점 + 판매 확정"을 하나의 DB 트랜잭션으로 처리해서, 여러 명이 동시에 같은 등급을 구매해도 같은 그림이 두 번 지급되지 않습니다.
- 일반 회원 로그인/회원가입은 **이메일·비밀번호 없이 Discord 로그인 하나**로만 이루어집니다. 웹과 봇 계정이 자동으로 같은 계정에 묶입니다.
- 디스코드 서버에서 **Administrator 권한**을 가진 사람은 별도 가입 없이 웹 관리자 패널에도 로그인할 수 있습니다.

## 빠른 시작

```bash
npm install
npx prisma migrate deploy   # 최초 1회: DB 스키마 생성
npm run seed                # 최초 1회: 관리자 계정 + 샘플 등급/그림/테스트 유저 생성
npm run dev                 # http://localhost:3000
```

실제 서비스를 시작하기 전에는 관리자 패널의 **관리자 설정 → 데모 데이터 정리**에서 시드 스크립트가 만든 테스트 회원/샘플 그림을 지우세요. (`/admin/settings`, 또는 봇의 `/데모데이터삭제`)

## 디스코드 봇 설정

1. [Discord Developer Portal](https://discord.com/developers/applications) → **New Application** 생성
2. **Bot** 탭 → **Reset Token**으로 토큰 발급 → `.env`의 `DISCORD_BOT_TOKEN`에 입력
3. **General Information** 탭의 **Application ID** → `.env`의 `DISCORD_CLIENT_ID`에 입력
4. (선택, 권장) 실제 운영에 쓸 서버 ID를 `DISCORD_GUILD_ID`에 입력
   - 비워두면 슬래시 커맨드가 전역 등록되지만 반영까지 최대 1시간 소요
   - 채워두면 "Discord 서버 관리자 로그인" 기능도 이 서버 기준으로 동작합니다
5. **OAuth2 → URL Generator**에서 scope `bot`, `applications.commands` 선택 → 권한은 기본값이면 충분 → 생성된 링크로 봇을 서버에 초대

설정이 끝나면:

```bash
npm run bot:deploy   # 슬래시 커맨드를 디스코드에 등록 (커맨드 목록이 바뀔 때마다 재실행)
npm run bot:dev      # 봇 실행 (파일 저장 시 자동 재시작)
```

## 디스코드 버튼 패널

명령어를 외울 필요 없이 버튼만 눌러서 이용할 수 있는 UI입니다. `/패널`, `/관리자패널` 모두 연동된 관리자만 실행할 수 있습니다.

- **`/패널`** — 관리자가 매장 채널에 걸어두고 안내하는 용도의 메인 패널. `[🛍️ 상품 보기]` `[💰 내 포인트]` `[🛒 장바구니]` `[📦 주문내역]` `[🎟️ 쿠폰함]` `[💬 문의하기]` 버튼이 있는 메시지가 올라옵니다 (버튼을 누르는 것은 관리자 본인 기준으로 동작합니다).
  - `상품 보기` → 등급을 고르는 드롭다운(Select Menu) → 선택하면 상세 정보 + `[구매하기]` `[장바구니 담기]` 버튼이 뜹니다.
  - `구매하기`를 누르면 그 자리에서 즉시 결제되고, 지급된 그림 이미지가 바로 표시됩니다.
  - `내 포인트` 화면의 `[계좌이체 충전 신청]` 버튼은 모달 창(금액/입금자명)을 띄웁니다.
  - `문의하기` 버튼도 모달 창(제목/내용)으로 바로 접수됩니다.
- **`/관리자패널`** — 연동된 관리자만 사용. `[💳 충전 대기]` `[💰 환불 대기]` `[💬 문의 대기]` `[📊 통계]` `[📋 등급 목록]` 버튼으로 대기 항목을 열람하고, 각 항목 옆의 `[승인]` `[거절]` 버튼으로 바로 처리합니다. 문의는 `[답변하기]` 버튼이 모달 창을 띄워 바로 답변을 등록합니다.

모든 관리자 비밀번호/2FA 코드 입력은 채팅에 노출되지 않는 **모달 창**으로만 이루어집니다.

## Discord 로그인(OAuth) 설정

일반 회원 로그인·가입과 관리자 로그인 모두에 "Discord로 계속하기" 버튼이 있습니다. 봇 설정에 더해 아래를 추가로 설정하세요.

1. Developer Portal의 같은 애플리케이션 → **OAuth2** 탭 → **Client Secret** 발급 → `.env`의 `DISCORD_CLIENT_SECRET`에 입력
2. 같은 탭의 **Redirects**에 아래 두 URL을 **모두** 등록 (배포 도메인이 있다면 그 도메인 기준으로):
   ```
   http://localhost:3000/api/auth/discord/callback
   http://localhost:3000/api/auth/discord/admin-callback
   ```
3. `.env`의 `DISCORD_OAUTH_REDIRECT_URI`가 위 첫 번째 URL과 일치하는지 확인 (두 번째는 자동으로 유추됩니다)

**동작 방식**

- 일반 사용자가 `/login`, `/signup`에서 "Discord로 로그인"을 누르면 → Discord 계정으로 즉시 로그인/가입됩니다 (봇에서 먼저 명령어를 써서 만들어진 계정이 있다면 그대로 연결됩니다).
- 관리자가 `/admin/login`에서 "Discord 서버 관리자로 로그인"을 누르면 → `DISCORD_GUILD_ID` 서버에서 **Administrator 권한**(또는 `DISCORD_ADMIN_ROLE_ID`로 지정한 역할)을 가지고 있는지 봇 토큰으로 확인합니다.
  - 권한이 있으면: 관리자 계정이 없었다면 **STAFF 권한으로 자동 생성**되고 즉시 로그인됩니다. (더 높은 권한이 필요하면 SUPER 관리자가 `/admin/security/admins`에서 올려주세요.)
  - 권한이 없으면: 로그인이 거부됩니다.

## 핵심 동작 원리

### 랜덤 지급의 안전장치 (재고 부족·중복 지급 방지)

```
구매 요청
  ↓
[하나의 DB 트랜잭션]
  포인트 잔액 확인 → 차감
  같은 등급의 "판매가능" 그림 중 하나를 원자적 UPDATE로 즉시 선점
    (WHERE status='AVAILABLE' 재확인 → 동시에 여러 주문이 와도 같은 그림이 두 번 선택될 수 없음)
  재고가 없으면 트랜잭션 전체 롤백 → 포인트도 차감되지 않음
  선점 성공 시 → 판매 확정(SOLD) + 주문 완료(COMPLETED)
  ↓
Discord DM 발송 (연동되어 있으면, 실패해도 구매엔 영향 없음)
```

포인트는 계좌이체를 관리자가 수동으로 입금 확인한 뒤에만 충전되는 "이미 확정된 잔액"이기 때문에, 카드/PG처럼 결제 승인을 기다릴 필요 없이 위 트랜잭션 하나로 안전하게 끝낼 수 있습니다.

### 환불 정책

- 기본적으로 **다운로드(열람)한 그림은 환불 시 재고로 복구되지 않습니다** (재판매 방지). `/admin/settings`에서 "다운로드한 상품도 환불 허용"으로 정책을 바꿀 수 있습니다.
- 환불 승인 시 결제했던 포인트가 그대로 환불됩니다.

### 관리자 자동 알림 (Discord DM)

디스코드 계정이 연동된 관리자 전원에게, 별도로 화면을 열어보지 않아도 아래 상황이 생기면 즉시 DM이 갑니다.

- 🚨 **재고 품절** / ⚠️ **재고 부족 임박** (등급별 남은 재고가 3개, 0개가 되는 순간에만 알림 — 이미 낮은 상태에서 팔릴 때마다 반복 알림이 오지 않도록 "그 순간"에만 발송됩니다)
- 📥 새 **포인트 충전 신청** / **환불 요청** / **1:1 문의** / **신고** 접수

### 데이터베이스 하나, 진입점 둘

`src/lib/`의 구매/포인트/환불/쿠폰 로직은 쿠키 세션에 의존하지 않는 순수 함수라서, 웹사이트의 서버 액션과 디스코드 봇 커맨드가 완전히 동일한 함수를 호출합니다. 즉 "웹에서만 되는 기능", "봇에서만 되는 기능"이 최대한 없도록 설계되어 있습니다.

## 프로젝트 구조

```
prisma/schema.prisma     DB 스키마 (SQLite, 개발용)
prisma/seed.ts           초기 데이터 시드 스크립트
src/lib/                 핵심 비즈니스 로직 (주문/포인트/환불/쿠폰/디스코드 알림) - 웹·봇 공용
src/lib/actions/         웹사이트 서버 액션 (쿠키 세션 기반 인증)
src/app/(shop)/          쇼핑몰 사용자 페이지 (자체 루트 레이아웃)
src/app/admin/           관리자 패널 (자체 루트 레이아웃 - 쇼핑몰 헤더와 완전 분리)
src/app/api/auth/discord/ Discord OAuth 로그인 라우트 (일반/관리자)
src/app/api/files/       그림 미리보기·다운로드 스트리밍 (소유권 검증 포함)
src/bot/                 디스코드 봇 (커맨드, 버튼/모달/셀렉트 패널, Discord 인증)
uploads/                 업로드된 그림 원본/미리보기 파일 (git에 커밋되지 않음)
```

## 배포 시 참고사항

- SQLite는 로컬 개발용입니다. 실제 운영 시 `prisma/schema.prisma`의 `datasource.provider`를 `postgresql` 등으로 바꾸고 `DATABASE_URL`을 교체하세요.
- `uploads/` 디렉터리는 서버 로컬 디스크에 저장됩니다. 여러 대의 서버로 수평 확장하려면 S3 등 오브젝트 스토리지로 교체가 필요합니다.
- 웹사이트와 봇은 **별도 프로세스**입니다 (`npm run dev` / `npm run bot:dev`). 배포 시 각각 독립적으로 띄우세요 (예: 웹은 Vercel, 봇은 상시 구동 가능한 서버/컨테이너).
- 슬래시 커맨드 목록을 바꾼 뒤에는 항상 `npm run bot:deploy`를 다시 실행해야 디스코드에 반영됩니다.
