# 입금알림 자동전달 (BankNotifier)

은행 앱의 입금 알림을 감지해서 샵 서버로 전달하고, 서버가 대기 중인 포인트 충전
신청과 금액+입금자명이 정확히 일치할 때만 자동으로 승인하는 안드로이드 앱입니다.

"자판기 판매"로 자기 이름의 샵을 운영 중이라면, 이 앱을 그대로 써서 **자기 샵**의
입금 자동승인을 돌릴 수 있습니다. 샵마다 웹훅 주소/비밀키가 전부 다르므로, 꼭 아래
순서대로 **자기 샵의 값**을 넣어야 합니다 (자비샵 본인 값을 그대로 쓰면 안 됩니다 -
서로 다른 샵이라 아예 적용되지 않습니다).

**이 폴더는 소스 코드만 있습니다.** 이 서버(리눅스, Android SDK 없음)에서는 `.apk`로
빌드할 수 없어서, 아래 순서대로 본인 PC의 Android Studio에서 직접 빌드해야 합니다.

## 왜 자동으로 승인하지 않을 때가 있나요? (중요)

아래 경우엔 **절대 자동 승인하지 않고**, 대신 디스코드로 관리자 전원에게 알림만 보냅니다.
반드시 `/admin/payments`(또는 봇의 `/충전목록`)에서 직접 확인 후 승인해주세요.

- 금액은 같은데 입금자명이 일치하는 대기 신청이 **없는** 경우
- 금액+입금자명이 일치하는 대기 신청이 **2건 이상**인 경우 (누가 보낸 건지 애매함)
- 알림 문구에서 금액/입금자명을 제대로 못 읽어낸 경우

잘못 자동 승인해서 실제로 입금 안 한 사람에게 포인트가 충전되는 사고보다, 사람이 한 번
더 보는 게 안전하다는 원칙으로 설계했습니다.

## 내 웹훅 주소 / 비밀키는 어디서 구하나요?

- **자비샵 본인 운영자**: 서버 `.env`의 `BANK_WEBHOOK_SECRET` 값을 씁니다.
- **"자판기 판매"로 산 테넌트 샵**: 구매(모달 제출) 직후 뜨는 "🎉 자판기 구매 완료"
  메시지에 **이 샵 전용** 웹훅 URL과 비밀키가 그대로 적혀 있습니다. 그 값을 그대로
  복사해서 쓰면 됩니다 (까먹었으면 관리자에게 `/admin` → 설정에서 다시 확인해달라고
  요청하세요 - 비밀키는 ShopSetting에 저장되어 있습니다).
- 비밀키는 **샵마다 전부 다릅니다** - 자비샵 본인 것이든 다른 테넌트 샵 것이든, 절대
  돌려쓰면 안 됩니다. 돌려쓰면 그 비밀키가 새는 순간 여러 샵의 웹훅이 동시에 위험해집니다.

## 앱 이름/문구를 내 샵에 맞게 바꾸고 싶다면

기본값은 "입금알림 자동전달"이라는 중립적인 이름입니다 (자비샵이라고 안 박혀있음).
자기 샵 이름을 넣고 싶으면 빌드하기 전에 딱 한 줄만 고치면 됩니다:

- `app/src/main/res/values/strings.xml`의 `app_name` 값을 원하는 이름으로 수정
  (예: `"OO샵 입금알림"`). 그 외 코드는 안 건드려도 정상 작동합니다.

## 빌드 방법

1. Android Studio 설치 (최신 버전 권장)
2. `android-notifier` 폴더를 **Open** (이 폴더 자체를 프로젝트로 열기)
3. Gradle Sync가 자동으로 진행됩니다 (인터넷 필요, AGP/Gradle 버전이 안 맞다고 뜨면
   Android Studio가 제안하는 "Upgrade" 버튼을 눌러 자동 업그레이드하면 됩니다)
4. 상단 메뉴 **Build → Build Bundle(s) / APK(s) → Build APK(s)**
5. 빌드된 `.apk`를 폰에 설치 (또는 USB로 연결해 **Run ▶** 버튼으로 바로 설치+실행)

## 폰에서 설정하는 방법 (단계별 자세히)

1. 앱을 실행하면 입력란 3개가 보입니다.
   - **서버 웹훅 URL**: 위 "내 웹훅 주소/비밀키는 어디서 구하나요?"에서 확인한 주소.
     형식은 `https://내샵주소.krl.kr/api/webhooks/bank-topup` 입니다 (끝까지 정확히
     입력 - 오타 나면 연결 자체가 실패합니다).
   - **비밀키**: 위에서 확인한 값을 그대로 붙여넣기. 앞뒤 공백 없이 정확히 일치해야
     합니다.
   - **은행 앱 패키지명**: 기본값은 `com.kebhana.hnbank`(하나은행 앱 추정)이지만, 다른
     은행이거나 정확한 값이 궁금하면 **휴대폰 설정 → 앱 → [내 은행 앱 이름]** 화면
     맨 위/상세정보에 적힌 패키지명을 확인해서 다르면 고쳐주세요. 패키지명이 틀리면
     알림을 아예 감지하지 못합니다 (자동승인도 전혀 동작 안 함).
2. 값 3개를 다 입력했으면 **저장** 버튼을 누릅니다. "저장되었습니다" 토스트가 뜨면 성공.
3. **알림 접근 권한 설정 열기** 버튼을 누릅니다.
   - 안드로이드 설정 화면으로 이동합니다. 목록에서 이 앱 이름(기본값 "입금알림
     자동전달", 또는 본인이 바꾼 이름)을 찾아서 켜주세요.
   - 안드로이드가 "이 앱이 모든 알림을 읽을 수 있게 됩니다" 같은 보안 경고를 띄울 수
     있습니다 - 확인을 눌러 허용해주세요 (은행 입금 알림만 보기 위해 필요한 권한입니다).
4. 앱으로 돌아와서 **테스트 전송** 버튼을 누릅니다.
   - "서버 연결 성공"이 뜨고, 디스코드로 관리자(들)에게 테스트 알림이 도착하면 설정이
     전부 정확합니다.
   - "연결 실패"가 뜨면: 웹훅 URL 오타, 비밀키 불일치, 또는 서버가 꺼져있는 경우입니다.
     URL/비밀키를 다시 확인해주세요.
5. **배터리 최적화 예외 설정**도 반드시 해주세요: **설정 → 배터리 → 앱별 배터리 사용 →
   이 앱 → "제한 없음"**. 이걸 안 하면 안드로이드가 알아서 앱을 꺼버려서, 폰을 며칠 안
   만지면 어느 순간부터 알림이 하나도 안 오게 됩니다 (가장 흔한 "갑자기 안 됨" 원인).
6. 이제 끝입니다. 실제로 입금이 오면 폰이 알림을 받는 즉시 자동으로 서버에 전달되고,
   금액+입금자명이 정확히 일치하는 대기 신청이 하나뿐이면 그 자리에서 자동 승인됩니다.

## 여러 개의 샵(테넌트)를 동시에 관리한다면

폰 1대에 이 앱은 1세트의 설정값만 저장합니다 (웹훅 URL/비밀키 각각 하나). 여러 샵의
입금을 같은 폰 하나로 자동승인하고 싶다면:

- 방법 A: 샵마다 이 앱을 **다른 패키지명으로** 따로 빌드해서 여러 개 설치 (가장 확실함).
  `app/build.gradle.kts`의 `applicationId`를 샵마다 다르게 바꾼 뒤 각각 빌드하세요.
- 방법 B: 입금 은행 계좌 자체가 샵마다 다른 폰/은행 앱을 쓰고 있다면, 그냥 각 폰에
  하나씩 설치해도 됩니다.

## 알림 문구 파싱이 안 맞으면

`BankNotificationListenerService.kt`의 `parseAmount()` / `parseDepositorName()` 함수가
정규식으로 금액/입금자명을 추출합니다. 실제 은행 알림 문구가 예상과 다르면 이 두
함수만 고치면 됩니다. 파싱에 실패해도 원문(`rawText`)은 그대로 서버로 전달되어 관리자
디스코드 알림에 표시되니, 급하면 파싱 실패 상태로도 수동 확인은 계속 가능합니다.

## 보안 주의사항

- 비밀키는 서버와 이 앱만 아는 값입니다. 캡처/공유하지 마세요. 샵마다 값이 다르니
  다른 샵 운영자와 비밀키를 주고받을 일 자체가 없어야 정상입니다.
- 이 앱은 자동 백업(`allowBackup=false`)을 꺼뒀습니다 - 비밀키가 클라우드 백업으로
  새는 것을 막기 위함입니다.
- 알림 접근 권한은 기기의 **모든** 알림을 읽을 수 있는 강력한 권한입니다. 이 앱은 설정된
  은행 앱 패키지명이 아닌 알림은 전부 무시하지만(코드 확인 가능), 신뢰할 수 있는 본인
  기기에만 설치하세요.
- (iOS는 지원하지 않습니다 - 애플이 다른 앱의 알림 내용을 읽는 공개 API를 제공하지
  않아서, 이 방식 자체가 iOS에서는 불가능합니다.)

## 플랫폼: 왜 Android만 있고 iOS 버전은 없나요?

이 앱의 핵심 동작(은행 앱이 띄우는 알림의 "내용"을 가로채서 읽는 것)은 Android의
`NotificationListenerService`라는 공개 API로 가능합니다. iOS는 샌드박스 정책상 한
앱이 다른 앱의 알림 내용을 읽는 기능 자체를 제공하지 않습니다(탈옥 없이는 불가능).
iOS에서 자동승인을 쓰고 싶다면 은행 알림 가로채기가 아닌 다른 방식(예: 은행 문자를
전달하는 단축어/자동화, 또는 오픈뱅킹 API 연동)이 필요하며, 이는 완전히 별도의
구현입니다.
